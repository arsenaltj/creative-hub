# VibeDock：从拆盒到日常使用的用户旅程检查

2026-09-23，按 PC 端 0.5 更新。依据当前 PC 伴侣程序、圆屏模拟器和项目验证记录；“硬件具备能力”与“本项目已接通”分开判断。在线网站是模拟演示，不能代替真机验收。

## 用户应该经历的完整流程

开机看到配对引导 → 在 Windows 安装并启动 VibeDock → 配对吧唧并检查屏幕、触控、麦克风/扬声器 → 选择 Codex 或 WorkBuddy 并确认真实数据可读 → 选定四个任务 → 抬眼看状态 → 点任务读最新输出 → 必要时在电脑打开原会话或处理请求 → 用原工具语音继续 → 断连、休眠或重启后可靠恢复。

## 最容易让用户困惑的四处

1. **“连接成功”不等于“可以完整使用”。** 蓝牙音频、触控控制、PC 服务和 Codex/WorkBuddy 数据源是不同连接。首次向导要逐项给出真实结果。
2. **“执行中”不等于“正在执行”。** 旧记录、未知状态和未开始的 `pending` 必须把证据时间展示出来；不确定时明确写待核对。
3. **“待介入”不等于“吧唧能批准”。** 没有请求身份、内容和回执时，按钮应是“在电脑处理”，不能假装已完成。
4. **“能看到状态”不等于“能读会话”。** 圆屏只适合最新进展与简短结果；PC 原会话承载全文、代码、diff 和复杂决定。

用户已确认吧唧没有屏幕下方的实体按键。当前演示全部使用圆屏触控：四区直接点任务；点中央打开功能菜单，进入“新会话 / 待处理 / 语音 / 切换工具”；用量从工具选择页进入。真机仍需分别验收四区、中央菜单、二级页与返回路径，不能把网页触控直接当作固件已实现。

## 建议的交付顺序与验收

**第一步：做成可用的最小真机链路。** Windows 安装/托盘 → 真机固件与配对 → 真实 Codex/WorkBuddy 状态显示 → 四槽管理 → 断连恢复。验收从一台未配置过的 Windows PC 和一枚新吧唧开始，用户能独立看到至少一个真实任务的状态与更新，并能分辨断连和旧数据。

**第二步：补齐核心操作。** 会话最新输出与 PC 全文跳转、原生语音定位与状态反馈、真实请求识别和安全处理。每项都要分别在两个真实客户端验证；某工具不支持的动作保持明确不可用，不用模拟成功代替。

**第三步：打磨长期使用。** 新任务提醒与换槽、隐私/锁屏、电量/休眠、固件更新、诊断与恢复。重点验证多任务高频更新、电脑休眠再唤醒、工具版本更新、配对丢失、两端同时处理请求。

当前公开网站只用于评审交互；尚不能作为上述真机链路的验收证据。项目当前能力边界见 [README](../README.md) 和 [验证记录](verification.md)。
