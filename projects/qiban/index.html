LOCAL RULES

事件记录

记录仅保存在本页内存；刷新即清空。

COMPANIONSHIP, WITH BOUNDARIES.

不是每一刻都表演，而是在合适的时候出现。

一条从早到晚的体验链路。所有动作都服从用户的操作；以下时间为演示情境，不是个人作息推断。

有陪伴感，也要有边界。

用户始终优先

不自动打开 App、不自动翻页、不代替用户点击。拖拽图标与桌面编辑拥有更高优先级。

数据最小化

只使用图标空间、桌面状态和经过授权的事件摘要。通知正文、联系人、验证码不进入萌宠上下文。

不为陪伴付出额外负担

离开桌面就暂停；一键关闭；通知风暴不连续追逐。第一版不依赖云端模型和跨 App 悬浮。

ANDROID NATIVE / LOCAL FIRST

桌面知道世界，规则决定行为，渲染负责表达。

Android 目标方案，不是本网站已接入的系统能力。现有 Launcher 继续掌管布局、图标点击与手势；萌宠是可关闭、可降级的增量层。

01 / SOURCE

Launcher + 系统适配

图标 Rect、页面、拖拽、电量、经过授权的通知摘要。

02 / CONTEXT

Desktop World

同一坐标系、不可变快照、版本号、用户资料隔离。

03 / POLICY

本地行为仲裁

生命周期门控、优先级、去重、冷却、过期取消。

04 / PLAN

落点与路径

图标避让、可见目标解析、路径失效检查、无路降级。

05 / RENDER

Android 动画层

Filament 候选 + 本地动作包；失效退回二维待机。

数据接入契约

需原生验证
信号目标来源边界
图标位置 / 当前页Launcher View + Model只读当前 Launcher
图标点击 / 拖拽桌面内部事件不抢原有手势
电量 / 充电BatteryManager / 广播被动更新
通知摘要授权后的通知适配层不传正文
可见 / 锁屏生命周期 + 系统状态隐藏即停绘
AI 任务完成用户授权的外部事件桥第二阶段

系统应用、默认桌面身份均不等于自动获得所有特权。原生权限需单独核对；跨用户、工作资料和不可见目标必须降级。

Kimodo 在哪？

仅作为 PC / 服务器侧离线动作生产候选。经重定向、脚滑检查和循环处理后生成端侧动作包；不放进每次通知的实时响应链路。网站角色由本地代码构造，未使用 Kimodo。
