# 栖伴：Android 桌面 3D 萌宠
## 产品需求与技术方案 · v1.0

版本日期：2026-09-22  
评审对象：产品、交互、Launcher 开发、图形、美术、测试与隐私团队  
文档状态：可用于方案评审与原生技术验证；不是已验收的 Android 产品说明。  
项目代号“栖伴”、角色名“栖栖”均为本次方案的暂定名称，不代表荣耀正式品牌。

> 产品主张：让一个有位置感、会回应、懂分寸的小伙伴生活在桌面里。不是重做整个 3D 桌面，而是在原有 Launcher 之上增加可关闭、可降级的陪伴层。

### 阅读约定

本文的功能、阈值、排期和预算属于产品设计建议；公开 API 能力标注参考资料编号。未检查荣耀内部代码、系统签名配置、权限白名单或设备实测，因此内部接入点和性能收益均须验证。网页里的系统状态全部模拟；网页通过不等于 Android 原生验收通过。

## 1. 产品定义与首版范围

### 1.1 面向谁，解决什么问题

面向愿意个性化桌面、喜欢角色陪伴，但不愿牺牲启动效率与续航的手机用户。对用户的价值不在于“画面更立体”，而在于角色能够利用位置、朝向、姿态和轻反馈，让通知、触摸、电量与昼夜变化产生可感知的空间关系。

首版验证三个假设：用户能理解它为何行动；用户愿意保留它；用户不会觉得它挡住操作或增加负担。以上是假设，不能用角色好看或点击次数多直接代替验证。

### 1.2 核心决策

| 决策项 | 首版方案 | 原因与边界 |
|---|---|---|
| 运行场景 | 集成于现有 Android Launcher | 复用布局、图标、启动和手势；不读取其他桌面的私有数据库 |
| 角色形态 | 单个两足拟人 Q 版角色 | 控制美术、骨骼、动作和适配复杂度；不是四足猫狗动作方案 |
| 视觉呈现 | 原有二维桌面 + 局部三维角色 | 不迁移所有图标到游戏引擎，不更换既有桌面排版 |
| 决策方式 | 本地事件 + 有限状态机 | 无网络时基础互动完整；首版无 LLM 运行时依赖 |
| 动作来源 | 一组经过审核的本地动作资产 | Kimodo 为离线资产生产候选，不是端侧或在线必选项 |
| 交互权责 | 用户操作始终优先 | 不自动点击、开 App、翻页、改布局或读消息正文 |
| 隐私策略 | 最小上下文、分项授权、默认不上传 | 系统应用身份不等于自动获得全部权限 |
| 跨 App 行为 | 首版不做 | 之前跨 App 桌宠的设想保留为独立后续方向，不与 Launcher 内首版混为一谈 |

### 1.3 范围分级

P0：显示与关闭、待机、点击宠物、拖动宠物、图标操作避让、当前页图标空间、布局变更取消、电量与充电、昼夜状态、通知摘要引导、轻打扰、锁屏与离场停绘、异常降级。

P1：自选角色、正式多动作包、通知来源白名单、外部 AI 任务完成桥接、折叠屏与平板专门体验、文件夹入口提示、少量低频自然语言指令。

明确不做：四足动物动作生成、持续屏幕识别、无障碍扫描其他应用、前台 App 使用画像、代用户执行 App 内操作、默认云端上传系统上下文、实时云端动作推理、重新实现全部 Launcher。

## 2. 体验原则与完整交互

### 2.1 六条必须成立的体验原则

用户触摸和桌面手势高于宠物自主行为；用户拒绝某项权限后仍可使用其他功能；角色不能成为隐形点击遮罩；一次事件只给适度回应；所有自主行为都允许取消；找不到安全位置就少做，不强行“聪明”。

没有主动事件时主要保持静止或低频呼吸眨眼，不强制每隔固定秒数走来走去。声音、振动默认关闭。夜间是低打扰规则，不是对用户睡眠状态的判断。

### 2.2 核心场景与验收口径

| 编号 | 触发与前提 | 角色反馈 | 结束、取消与降级 |
|---|---|---|---|
| F01 初次进入 | 用户主动开启；桌面可见 | 在安全空位出现，简短挥手 | 不强制申请通知权限；无安全空位则提示调整或使用小尺寸静态形态 |
| F02 轻触宠物 | 命中宠物实际触摸区域 | 看向用户、挥手或轻跃，约 1–3 秒 | 可打断自主动作；夜间短暂回应后回睡眠 |
| F03 拖动宠物 | 按下后移动超过系统触摸阈值 | 跟手移动、抱起姿态 | 松手校验安全落点；无效位置吸附到最近可用点；取消手势也要落稳 |
| F04 图标拖拽 | 桌面确认进入拖拽/编辑状态 | 停止当前追逐，移开或淡出 | 不改变图标拖拽事件流；图标落下后重新采样布局 |
| F05 通知引导 | 已授权、当前可见、允许打扰 | 解析对应图标；走到邻近空位，朝向目标 | 不开 App、不自动翻页；目标不可见、路径失败或授权撤销立即降级 |
| F06 低电量 | 电量 ≤15%，且未充电 | 低活力姿态，减少主动动效 | 电量 ≥20% 才退出低电量态，避免来回震荡 |
| F07 接入充电 | charging 从 false 变 true | 短暂庆祝一次 | 夜间/轻打扰可抑制；后续电量刷新不重复庆祝 |
| F08 夜间状态 | 用户配置时间段或主动切换 | 安静睡眠，减少主动移动 | 触摸可短暂唤醒；不强制读取健康、日历或作息数据 |
| F09 点击 App | Launcher 正常处理应用启动 | 立即让出场景 | 确认离场后停止动画与渲染；不跨 App 跟随 |
| F10 锁屏/灭屏 | 桌面不可见或设备进入锁定/非交互状态 | 隐藏并取消动作 | 清除待执行敏感事件；回来后不重放过期事件 |
| F11 页面/布局改变 | 切页、图标移动、旋转、折叠、网格改变 | 中止依赖旧布局的动作 | 完成布局后生成新版本；只有新快照上的目标可以继续 |
| F12 用户关闭 | 设置中关闭萌宠 | 立即停止显示与自主任务 | 不后台轮询，不反复劝用户开启 |
| X01 外部 AI 完成 | 经认证的扩展事件；P1 | 短暂庆祝并可提供用户主动查看入口 | 禁止未校验外部消息直接触发系统操作；网页只模拟 |

时间和电量阈值是初始产品规则，不是 Android 平台要求。动作时长还需与正式美术动画及用户测试一起确定。

### 2.3 通知引导的完整链路

接收通知回调 → 验证授权与资料身份 → 仅提取允许字段 → 过滤静默/持续型等不适宜事件 → 去重与冷却 → 确认桌面可见、未编辑、允许打扰 → 解析可见图标 → 选择空位并规划路径 → 执行前再次校验布局版本 → 移动、朝向与轻提示 → 回到环境待机。

图标关联不能只依赖包名。对象身份至少区分用户资料、应用组件、桌面实例；通知通常只有包级关联时，应由目标解析器选择当前页匹配的应用入口，而不是假定它唯一对应某个快捷方式。重复图标优先选当前页可见且容易接近的实例；工作资料不可访问时不跨资料猜测。

目标在其他页面：原地轻提示，不自动翻页。目标在关闭的文件夹中：首版降级为原地提示，P1 才考虑指向文件夹入口。不存在快捷入口：原地轻提示。无路可走：原地朝向或完全不做。用户已经点开应用：立即取消引导。

通知引导不应展示原始联系人、标题、正文、图片或验证码。通知角标只是摘要性示意；需要了解内容时由用户主动通过系统通知或 App 查看。

### 2.4 设置、入口与退出

建议入口：桌面设置 > 个性化 > 桌面萌宠。默认关闭，首次由用户主动开启；角色初次出现的欢迎说明只展示一次。

设置最小项：总开关、显示大小、轻打扰、夜间时间段、通知引导分项开关、通知来源选择、低动态效果、恢复默认位置。正式通知能力在用户主动启用时解释用途并进入系统授权流程；未授权仍可体验摸摸、拖动、电量和时间。

长按宠物可进入小菜单，包含“安静一会儿”“移动位置”“桌面萌宠设置”“关闭”。具体长按/拖拽判定应沿用桌面手势规范，不用网页鼠标阈值直接替代 Android 触摸阈值。

此处的完整设置页、长按菜单、首次引导与多角色选择属于 PRD 要求，网页未全部实现，不应宣称已完成。

## 3. 行为仲裁与异常处理

### 3.1 分层优先级

| 优先层 | 典型事件 | 仲裁规则 |
|---|---|---|
| L0 生命周期与关闭 | 锁屏、非交互、桌面离场、总开关关闭 | 取消全部动作；隐藏；停止帧回调；高于其他一切 |
| L1 用户操作安全 | 桌面编辑、图标拖动、系统转场 | 避让或隐藏；拒绝新自主移动；不抢事件流 |
| L2 用户主动互动 | 点宠物、拖宠物 | 在可见前提下立即响应；同一触摸指针只由一个对象消费 |
| L3 环境约束 | 夜间、轻打扰、低电量、温控降级 | 决定后续动作是否允许与表现强度；不是不断插队的动画 |
| L4 提示事件 | 通知、充电边沿、外部任务完成 | 经去重、冷却与可见目标校验后，执行短暂动作 |
| L5 自主待机 | 呼吸、眨眼、偶尔朝向 | 仅在前述层级均无工作时运行 |

生命周期、用户操作、环境约束与具体动作应分开建模，避免单一枚举承载所有条件。例如夜间仍然可以响应用户主动点击，但不应被一条通知唤醒追逐。

### 3.2 去重、冷却与过期

生产建议：同一通知 key 的更新合并；同一来源主动移动冷却 60 秒；全局主动提示上限 3 次/分钟；待处理提示最多保留一个最新摘要，TTL 30 秒。夜间与用户轻打扰直接抑制自主追逐，不在解除限制后集中补演。

网页为了便于演示，将同源通知冷却缩短为 3 秒，并不实现生产级通知排名、全局限流或所有系统事件队列。两种配置必须显式区分。

动作对象建议携带 actionId、generation、layoutVersion、userProfileId、expiresAtElapsed。每次切页、隐藏、撤权或重规划都使 generation 递增。任何延迟回调、资源加载结果或在线结果返回后先校验代次；不符合就丢弃，不能覆盖新状态。

### 3.3 降级表

| 失败条件 | 期望行为 | 禁止行为 |
|---|---|---|
| 通知未授权/被撤销 | 停止通知摘要输入，清空相关待执行动作 | 截图、无障碍或其他渠道绕过用户拒绝 |
| 目标不在当前页 | 原地轻提示或静默 | 自动翻页、使用上一页坐标 |
| 工作资料受策略限制 | 不关联该资料目标 | 用同包名个人图标冒充工作资料目标 |
| 路径无解/桌面拥挤 | 原地朝向、缩小至允许尺寸或隐藏 | 穿越拖拽区域，挡住用户操作 |
| 布局版本过期 | 取消、重采样、按需重规划 | 继续执行旧路径直到播放完 |
| 模型/动作资源损坏 | 回到内置静态/二维角色，记录故障 | 导致 Launcher 崩溃或无法点击图标 |
| Surface/渲染上下文丢失 | 重建资源或降级；保证 Launcher 正常工作 | 无限重建、后台持续占用 GPU |
| 数据入口断连 | 标记来源不可用，不使用过期状态装作实时 | 轮询隐私接口补全，或推断未知状态 |

## 4. 数据来源、授权与坐标体系

### 4.1 首版数据注册表

| 数据 | 建议来源 | 更新方式 | 权限/可信边界 |
|---|---|---|---|
| 当前页、图标实例、容器 | 本 Launcher 的 Model/Workspace 适配器 | 页面、绑定、增删、拖拽提交时发布 | AOSP Workspace 有页面及图标/文件夹/Widget；荣耀具体接口需内部核对 [R1] |
| 图标可见矩形 | 当前布局完成后的 View，统一映射到宠物 Overlay 坐标 | 布局稳定后批量采样；转场期间暂停或发布变换 | 不以数据库格子坐标冒充实际显示坐标 [R2][R3] |
| 图标点击/拖拽/编辑 | Launcher 已有输入与事件管线 | 原事件后附加只读语义事件 | 不能改变原来的启动与拖拽职责 |
| 电量、充电 | BatteryManager 与 ACTION_BATTERY_CHANGED 等系统广播 | 初始快照 + 被动更新 | 官方介绍了充电状态与电量读取方式；不需申请电池优化豁免来读取 [R4] |
| 通知摘要 | 已授权的 NotificationListenerService 或经过审计的内部通知适配服务 | 连接成功后处理 posted/removed/ranking 回调 | 需要单独确认授权；工作资料可能被设备策略限制 [R5][R6] |
| 时间情境 | 设备本地时间 + 用户设置 | 仅在相关时间边界或配置变化时更新 | 不读日历，不推断用户是否真的睡着 |
| 交互/锁定状态 | 桌面生命周期及可信可见状态，辅以 PowerManager / KeyguardManager | 状态变化时门控 | 各状态语义不同，不用一个 onPause 或亮屏布尔值代表完整可见性 [R7][R8] |
| 外部 AI 完成 | 独立事件桥，P1 | 显式认证的任务事件 | 需单独实现，不属于 Android 自带系统状态 |

LauncherApps 可用于查询可启动应用、资料及部分相关能力，但不是读取其他 Launcher 图标布局的公共 API。首版布局来自自身桌面，不读取其他桌面的内部数据库。[R9]

系统默认桌面、系统预装、平台签名和特权权限白名单是不同概念。不能仅因“在荣耀桌面内开发”就默认获得任意系统服务权限；必须由实际 manifest、签名、权限配置及系统服务契约证明。

### 4.2 通知权限必须说清楚

NotificationListenerService 的 manifest 声明、系统绑定和用户通知访问批准是不同事项。服务应等待 onListenerConnected 后再进行相关操作；isNotificationListenerAccessGranted 可检查本应用监听服务是否被用户批准。[R5][R6]

POST_NOTIFICATIONS 是应用发送通知的运行时权限，不等于读取其他应用通知的访问授权。[R10] 本方案首版甚至可以不向用户发送额外通知，只响应经过授权的系统摘要。

即便业务只消费应用标识，系统通知访问授权本身可能比这更宽。告知用户时不能把授权范围描述成“只允许读包名”。技术实现应在受控适配层内立即白名单提取字段，禁止把完整通知对象、extras、标题正文或附件传入行为引擎、日志、分析和云端。

### 4.3 统一坐标：先解决真实位置，再做归一化

区分布局格子、View 局部、窗口、屏幕、宠物 Overlay 和三维世界坐标。数据库中的 screenId/cellX/cellY 只能提供布局意图；动画平移、缩放、滚动、横竖屏、折叠与窗口 Insets 会改变实际显示位置。

静态平移场景可以用图标和 Overlay 在屏幕上的位置差转换坐标；存在缩放旋转时，应将四个角点通过完整变换链映射，不能只做 left/top 相减。Android View 与屏幕坐标接口、Insets 官方说明提供基础语义，但实际 Launcher 的变换链需要按工程实现验证。[R2][R3]

约定本地规划坐标为 Overlay 局部逻辑坐标，触摸和避障距离用 dp 或该坐标中的实际长度。归一化坐标用于存储、跨窗口传递与演示，不把 0–1 的横纵单位当成相同距离。重建布局后，重新计算可用落点，不认为保持归一化坐标就自动完成折叠屏适配。

保留字段：displayId、profileId、pageId、layoutVersion、transformVersion、viewportSize、safeInsets、exclusionRects。对象保留 stableItemId、packageName、componentName（可选）、shortcutId（可选）、containerId、rectInOverlay、visible、enabled。

### 4.4 从二维桌面到三维角色空间

首版采用二维导航 + 三维角色表达。对每个候选脚底落点，使用固定相机把角色投影到屏幕，得到视觉包围与有效触摸区域；对图标、文字、Widget、Dock、手势区、显示挖孔和折叠铰链做保守膨胀，得到可行走区域。

首选“图标旁可用空位”，不是图标中心。没有合适落点就只朝向目标。可以用小型网格 A* 或可见性图规划，不需要第一版引入完整物理引擎；路径随 layoutVersion 失效，不能用全局平滑把路径圆角穿进障碍物。

角色朝向和指向使用投影后的目标矢量。移动速度与本地行走循环一起校准；首版可用 in-place 动作加轨迹位移，但必须检查脚滑，不能同时叠加动作 root motion 导致位移翻倍。

## 5. Android 技术架构

### 5.1 推荐分层

```text
Launcher Model / View / Input       Authorized System Adapters
                |                              |
                +--------- Context Adapter ----+
                                |
                    Desktop World Snapshot
                                |
                  Policy + Behavior Arbiter
                                |
                   Target Resolver + Planner
                                |
                   Motion Player + Renderer
                                |
                  Pet Layer inside Launcher

Offline asset pipeline -> reviewed motion pack -> local asset store
```

Launcher 仍是图标、布局、页码、启动与手势的唯一权威。萌宠模块只消费经过适配的数据；不在渲染器、AI 或新数据库里再维护一份可写的桌面布局。

### 5.2 模块职责与线程边界

| 模块 | 输入/输出 | 执行与失效规则 |
|---|---|---|
| LauncherContextAdapter | 真实 View/Model → 不可变布局快照 | UI 线程读取视图；合并一帧内重复变更；不向工作线程泄漏 View |
| SystemStateAdapter | 电量、可见状态、授权摘要 → 类型化事件 | 回调快速返回；原始敏感对象只留在适配边界 |
| ContextStore | 快照 + 事件 → 当前有效世界 | 单一序列化更新点；每个来源可标记 available/stale/denied |
| BehaviorArbiter | 当前世界 → 行为意图 | 本地规则；可取消；不阻塞 Launcher 主线程 |
| TargetResolver/Planner | 意图 + 当前布局 → 目标与路线 | 后台计算；结果带版本；返回前后均可取消 |
| MotionPlayer | 动作意图 + 时间 → 本地动画姿态 | 骨骼映射、过渡、循环、朝向、脚接触；不拥有系统权限 |
| PetRenderer | 姿态 + 相机 → 宠物图层 | 渲染资源在指定渲染线程管理；失效降级，不拖垮桌面 |
| Diagnostics | 脱敏事件码 → 本地调试信息 | 发布版默认关闭详细日志；不得包含通知正文或用户布局明细 |

这些类名为建议契约，不是对荣耀工程现有类名的断言。先找到工程真实接入点，再写对应适配器。

### 5.3 渲染技术选型

建议先验证原生 Launcher + Filament/gltfio + GLB 动作资产。Filament 官方提供 Android 支持及 glTF 2.0 加载组件，因此可作为此增量层的候选。[R11] 这不意味着已经证明它在荣耀桌面上功耗最低或包体最小。

SurfaceView 与 TextureView 的透明合成、层级、转场和输入协同应做同场景对照；不能只凭理论直接定最终承载方式。角色包围之外不拦触摸，且在与原生图标/系统手势冲突时优先交还 Launcher。

Unity/Godot 可用于独立体验或动作验证；如果团队已有成熟相关运行时，可以对照验证。但首版不为一个角色自动嵌入完整游戏业务栈。复用优先于引入框架，不以“用了游戏引擎”作为成功标准。

### 5.4 Kimodo 的明确位置

Kimodo 官方定位为人类/人形运动生成研究实现，支持以文本与约束生成运动；它不是照片生成三维外观的模型。[R12][R13] 本方案只将其放在离线资产制作路线中，具体导出格式与转换器以选定版本的官方文档和实测为准。

候选链路：文本动作描述 → Kimodo 生成源骨架动作 → 美术工具重定向到栖栖骨架 → 修正大头短腿比例、穿模和脚滑 → 制作循环与过渡 → 导出可加载的动作包 → Android 本地播放。

先用 8–12 个干净可控动作完成闭环：待机、走、转向、挥手、指向、点按反馈、抱起、低活力、睡眠、庆祝。只有其资产产出质量优于已有动作制作方式时，再扩大 Kimodo 资产流水线。代码、模型权重、训练数据和生成资产的授权条件分别核对，不因代码公开就推断全部可以商用。

当前网站角色由代码生成，共享三维姿态并优先使用 WebGL；无 WebGL 时用 Canvas2D 投影与分层着色兼容显示。没有接入 Kimodo、自动骨骼绑定、真实 GLB 或云端动作模型。

### 6.3 生命周期不变量

HIDDEN 状态下，宠物渲染帧回调为零、无自主移动、无持续唤醒锁、无用于陪伴的后台轮询。恢复时先重建可见布局，再恢复基础姿态；不立即补演离场期间的历史通知。

Surface 销毁时取消动画驱动、释放或托管图形资源；资源重建结果必须校验 generation。内存压力时可卸载非必要动作/贴图。禁止业务代码绕过统一的生命周期门控直接操作角色。

## 7. 性能、隐私与可访问性

### 7.1 首轮建议预算，不是实测结论

| 项目 | 初始验收目标 | 测量条件与说明 |
|---|---|---|
| 本地主动触摸首反馈 | P95 ≤100 ms | 从输入到首个可见反馈；需真机端到端打点 |
| 通知首反馈 | P95 ≤300 ms | 从本地适配层接收合格事件计时，不包含上游推送延迟和走完整条路径 |
| 活跃动作 | 基线 30 FPS | 是否需要 60 FPS 由体验收益与功耗决定；不是承诺所有机型达标 |
| 静止/睡眠 | 静止可停帧；低动态建议 ≤10 FPS | 完全遮挡、离场、锁屏必须停止宠物渲染循环 |
| Launcher 主线程新增工作 | 关键回调 P95 ≤2 ms | 快照采样、回调、仲裁分别标记；重任务移出 UI 线程 |
| 包体增量 | 首角色与必需运行时初始目标 ≤20 MB | 按生产 ABI、安装交付方式与压缩方式测量；可能需调整 |
| 常驻内存增量 | 初始目标 PSS ≤60 MB | 记录原生堆、图形内存、资源缓存；不能只看 Java 堆 |
| 稳态耗电增量 | 屏幕亮起空闲场景目标 ≤5% 相对功率增量 | 与关闭萌宠的同机基线比较；固定亮度/温度/刷新率，至少三轮交替测量 |
| 稳定性 | 不引入 Launcher 崩溃、启动阻塞与手势故障 | 不能以短时冒烟测试代替回归与长稳 |

这些预算用于让团队尽早发现不划算的方案，不是已测得的效果。若超过预算，优先减少绘制/透明合成成本、压缩动作与贴图、静态待机或使用二维降级，再讨论是否扩大投入。

采用 Macrobenchmark 的启动/帧时序等指标与 Perfetto 跟踪进行对照；官方指标能力可见 [R14]。记录设备、系统构建、刷新率、亮度、温度、APK/资源版本以及是否开启温控降级，报告分位数与重复实验结果，而不是只展示平均帧率。

### 7.2 隐私与控制

第一版不调用云端 LLM，不上传通知、图标布局或应用清单。总开关、通知开关、来源选择和低打扰必须可理解、可撤回。拒绝不影响无关功能；权限撤销即时清空待执行摘要。

正式诊断优先记录事件码、耗时、失败分类和版本，不保存具体消息内容、联系人与完整桌面排列。需要上传调试材料时另行取得用户授权，限定范围、留存期限和访问者。

本产品的轻打扰设置不等于修改系统勿扰模式。系统勿扰的读取或遵循方式，应按实际授权和内部契约确认；不为陪伴功能要求修改系统通知策略的高权限。

### 7.3 可访问性与易用性

遵循系统减少动态效果偏好；支持关闭主动移动、声音与振动。宠物拥有可读名称和明确开关；不频繁通过读屏播报自主动作，不让焦点自动跳到宠物。桌面图标和手势仍保持原有可访问性语义与命中规则。

正式角色拖拽区域、字号、气泡和控制按钮按照 Android 的交互规范验收；网页的 CSS 像素不是 Android dp 指标。气泡不能覆盖图标、系统关键信息和手势区域，放不下则缩短或不显示。

## 8. 实施路线与验收计划

### 8.1 按可验证闭环推进，不按模型能力堆砌

M0 / 确认原生边界：核对 Launcher 接入点、权限、Overlay 坐标、可见信号、转场与渲染承载方式。产出实际接口映射和对照测量方案；未确认前不写“已接通系统状态”。

M1 / 最小原生闭环：一个角色 + 自身布局快照 + 点击/拖动 + 离场停绘。先验证手势不回归、坐标正确、运行时可取消；不依赖通知授权与 Kimodo。

M2 / 事件陪伴：加入电量、充电边沿、夜间、授权通知摘要和图标引导；完成过期取消、冷却、无路与目标不可见降级。网页只是这一阶段的体验参考。

M3 / 生产质量：正式动作资产、资源降级、崩溃隔离、功耗对照、原生设置/授权/无障碍、灰度开关和用户测试。达到质量门槛后再扩充角色与外部事件。

M4 / 独立后续：自定义照片生角色、自动绑定、Kimodo 动作流水线、少量低频语义意图、外部 AI 任务桥。每项都单独评估授权、成本和失败模式；不作为首版必须条件。

建议职责：Launcher 工程负责人定义数据与输入契约；图形负责人负责渲染和停绘；美术/动画负责角色资产与骨骼；交互负责低打扰与可发现性；测试/隐私负责人负责边界和回归。未核实团队人数与设备，不把阶段写成确定交付日期。

## 9. 本次网站交付与边界

### 9.1 已实现的网页范围

网站提供四个页面区域：交互实验室、用户旅程、技术架构和内嵌 PRD。交互包含摸摸/拖宠物、模拟消息、真实 DOM 图标拖拽换位、脚底落点与 A* 路径、低电量/充电、夜间、轻打扰、模拟撤权、切页、点击 App 离场、模拟锁屏、一键故事演示和本地事件记录。

工程视图可以查看当前 DOM 图标矩形、布局版本、目标路径、脚底位置和 JSON 快照。可以导出模拟状态与事件记录。外部 AI 任务完成仅为预留扩展事件的交互示意，没有真实账户接入。

网站为单文件离线入口，无第三方脚本、在线字体、遥测或后台服务依赖。源码包保留可编辑脚本与构建脚本；它是体验参考，不是 Android 原生代码。

### 9.2 不应被误解的地方

网站没有访问 Android 系统 API；网页开关不改变手机权限。角色是原创程序化占位模型，未接入 Kimodo。优先尝试 WebGL，无法使用时切换为基于三维姿态投影的 Canvas2D 兼容渲染；兼容模式不等同于 GPU 物理渲染。

网站仅验证演示交互与事件逻辑，不验证真实通知 ranking、用户资料权限、系统签名、Surface 合成、GPU 驱动、原生电耗、后台策略、触摸透传与正式动作重定向。正式启动/设置/长按菜单、生产级通知风暴限流、多角色资产导入、折叠屏/平板真机均未完成。

该文件可本地打开或放入静态站点目录。除非另有实际部署结果，不应把文件链接称为已经上线的公网网站。浏览器自动化测试与 Android 真机测试应分别记录，不合并结论。

### 9.3 推荐评审顺序

先运行一键故事，理解从触摸到夜间的连续体验。再手动试通知、拖图标与切页。接着关闭通知访问、开启轻打扰、进入模拟 App 或锁屏，验证角色知道什么时候不做。最后查看技术架构和 PRD，对照哪些是网页演示，哪些还要原生接入与实测。

## 10. 待团队确认的关键问题

在 M0 前确认以下事项：荣耀 Launcher 是否提供稳定的只读事件订阅点；可见性与系统转场能否准确门控；通知是否已有可复用且合法授权的内部摘要服务；基线设备与系统版本范围；正式角色资产与动画制作能力；允许的包体/内存/功率预算；生产设置入口与灰度开关负责人。
