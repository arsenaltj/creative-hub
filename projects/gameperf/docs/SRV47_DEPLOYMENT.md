## 已解决的本机环境问题

远程终端子进程曾缺少 `ProgramData`：`ssh -V` 退出 255 且无输出。只在子进程补齐 Windows 已知目录后，同一命令返回 0；随后真实 SSH 查询成功。这不是修改系统全局环境，也不代表任意 SSH 失败都可用此法修复。

```powershell
# 仅在当前 PowerShell 进程缺少该变量时补齐：
if (-not $env:ProgramData) {
    $env:ProgramData = [Environment]::GetFolderPath('CommonApplicationData')
}
# 只在本机填写实际值，不提交到 Git：
$env:GP_EXPECTED_HOST = '<实际且已批准的服务器地址>'
# 默认仅展示计划，不连接服务器：
.\scripts\inspect-srv47.ps1 -ServerCtlPath '<现有serverctl.ps1完整路径>'
# 核对脚本、目标和影响后加 -Run，仍有 INSPECT 确认。
```

## 上线顺序

1. 定位既有管理脚本，核对别名解析的目标；确认 SSH 主机密钥校验；只读复查资源、工具、端口、既有站点及数据批准范围。
2. 选择独立应用目录。当前未找到 Docker，不直接执行 Docker 路径、不默认安装系统软件。先确认采用已有 Python 虚拟环境部署还是另行批准安装 Docker。两条路径均保留账号权限和数据目录边界。
3. 先绑定服务器 `127.0.0.1:8765`。使用本机 SSH 隧道检查健康接口、匿名业务 API 返回 401、实际浏览器登录、角色、版本冲突、刷新/重登/重启后的持久化。
4. 账号密码在受信任终端交互创建，不进入聊天、仓库、前端或命令参数；没有默认密码。
5. 先完成独立应用与数据库备份/恢复验收；再确认子域名、DNS 和既有 Caddy 的受控配置入口。
6. 新增独立站点反代到本机端口，备份、validate 通过后才按既有管理方式 reload；复查新旧站点。失败只回退本次更改，不重启代理、不破坏既有数据。
