# 从蓝图到业务系统的工程边界

## 当前实现

浏览器 → 同源 REST API → SQLite（任务、证据引用、版本、用户、会话、审计）。

现有调参 Agent → 写入型接口 → 新任务 / 实验草稿 → 人工核验 → 独立审核记录。

蓝图节点保存为记录，有 group 与 parentId；支持新增与子能力拆分，并拒绝父子循环。当前是结构化能力图，不是任意拖拽的无限画布或可直接运行的工作流编辑器。业务任务关联节点，实验关联任务；媒体和用户反馈经人工检查后转换为任务。

产品实验和 Agent 方法候选分别存储，独立审核。节点与任务状态的人工维护不代表真实设备连接，也不表示系统已自动完成了实验。

## 为什么第一版保持轻量

已有的高通调参 Agent 不搬进本服务。本工作台只统一目标、任务、实验和证据的可见入口，避免尚未明确接口就重建整个研发平台。

前端无构建链，方便直接维护 UI；后端契约与持久化分离。初期单实例、单工作空间。并发写入使用 SQLite 事务与记录版本约束，不提供企业高并发或跨地域一致性承诺。

## 下一轮接入顺序

1. 映射已有 Agent、构建、刷机、采集、搜索和评测工具，确认调用边界；只补必要适配层。
2. 使用一个脱敏、可复现任务验证结果回传、任务关联与证据路径，不先授权远程控制。
3. 真机执行器作为独立服务，具备设备租约、互斥、超时、停止与恢复机制；单独设计命令白名单和权限。不得给这个 Web 服务直接拼接 Shell 的能力。
4. 独立评测器从冻结证据和固定验收版本生成机器可核对的评测报告；与候选生成权限分离。首版人工审核记录不充当该评测器。
5. 方法晋升通过候选注册表和版本发布接口逐步接入；不得因网页状态变成 accepted 就自动替换线上 Agent。
6. 规模扩大后再引入 SSO、分项目 RBAC、对象存储、消息队列和 PostgreSQL。基于实际负载决策，不以技术组件数量验收。

## 版本边界

界面与运行代码：0.2.0。设计底稿：docs/blueprint-v0.1.md。数据格式：schema 1。

源代码更新不自动修改数据库中已经维护过的节点。修改 `app/seed.json` 只影响新数据库，避免升级覆盖人工记录。后续种子变化须提供显式迁移和冲突处理。

已提交证据不可直接改写，需要新候选；旧审核和失败记录保留。审计表没有删除 API，但数据库管理员仍可改动，不能称作防篡改审计。

## 非目标

没有自动代码修改、任意远程执行、真机队列、自动采集、性能优化算法、基础模型训练、递归自改进引擎或公开匿名分享。

本地体验版是演示与草稿载体，不具备服务器权限边界。真实角色限制只在后端执行。业务上线、工作数据离开公司网络、供应商代码使用等都需要独立授权。
